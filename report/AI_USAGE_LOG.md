## #1 · 2026-11-26 · 프로젝트 명세 작성

**요청 (전문)**

> 이제부터 외판원 문제(TSP)의 근사 해법을 비교하는 프로젝트를 진행할 거야.
> 평면 위 n개 점의 순회 경로를 세 방식(최근접 이웃, MST 2-근사, 2-opt)으로 구하고, 같은 조건에서 속도·품질을 비교할거야.
>
> 구현해야하는 항목은 다음과 같아.
> - 최근접 이웃 / MST 2-근사 / 2-opt 방식의 TSP 문제 해결 코드
> - Held-Karp DP를 통해 작은 n에서 최적값을 계산해 기준값으로 이용
>
> 비교기준은 속도, 품질 등이야.
> 실행 시간 혹은 거리 계산 횟수로 속도를 측정하고, 품질은 각 알고리즘이 출력한 경로의 거리가 최적값으로부터 벗어난 정도를 최적 길이로 나눠서 계산할거야. n이 변화함에 따라 달라지는 정도도 출력해보고 실제 이론값과 얼마나 같은지도 확인할거야.
>
> 실험은 다양한 입력 유형(무작위, 군집형, TSPLIB)을 설정해서 진행할거고 최적을 알 수 있는 14보다 작은 n에서는 최적값과 비교를 진행할 거고, 더 큰 n에서는 각 프로그램 끼리 비교할거야. 조합마다 seed는 고정해서 재현할 수 있게 만들어줘.
>
> Readme에는 프로젝트 개요와 함께 진행한 실험들을 재현할 수 있게 설치 및 실행 방법과 환경 등을 남겨줘.
>
> 개발을 진행하면서 코드를 검증할 수 있는 테스트도 필요해. 실제로 알고리즘이 뱉은 경로가 유효(모든 노드 순회 여부)한지 등의 테스트를 만들어서 개발과정에서 이용해.
>
> 우선 전체적인 명세를 작성해줘. 내가 검토하고 직접 수정하거나 수정할 부분 알려줄게. 이 요청부터 모든 요청(전문)과 네 응답 및 처리(요약)는 AI_USAGE_LOG.md에 기록해줘.

**응답 및 처리 (요약)**

- `SPEC.md`에 명세 초안을 작성했다. 코드는 쓰지 않았다.
- 명세에 담은 내용:
  - 목표
  - 구현 항목 4개와 각각의 이론 시간·품질 보장
  - 입력 유형 3개와 seed 규칙
  - 비교 기준 4개(속도, 품질, 확장성, 이론 대조)
  - 실험 A(작은 n, Held-Karp 대비), B(큰 n, 상호 비교), C(TSPLIB, 알려진 최적값 대비)
  - 테스트 항목, 저장소 구성, README 내용, 환경, 범위 밖 항목
- 요청과 중간 발표가 다르거나 정해지지 않은 부분은 `[검토]`로 표시했다.
  - 격자 입력을 뺄지
  - n = 14를 포함할지
  - 큰 n에서 MST 하한 비율을 함께 쓸지
  - 2-opt를 n ≤ 1000으로 제한할지
  - TSPLIB 다운로드 허락
  - 테스트 도구
