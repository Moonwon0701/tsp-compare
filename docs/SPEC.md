# 명세: 외판원 문제(TSP) 근사 해법 비교

> 상태: v1 (2026-11-26 확정)

## 1. 목표

평면 위 n개 점의 순회 경로를 세 근사 해법으로 구하고, 같은 조건에서 **속도**와 **품질**을 비교한다. 측정값이 이론(시간 복잡도, 근사 보장)과 맞는지도 확인한다.

## 2. 구현 항목

| 모듈 | 방식 | 이론 시간 | 품질 보장 |
|---|---|---|---|
| `nearest_neighbor` | 시작점에서 가장 가까운 미방문 점으로 반복 이동 | O(n²) | 없음 (최악 약 ½·log₂n 배) |
| `mst_approx` | Prim으로 MST를 만든 뒤 전위 순회하고, 중복 방문점은 건너뜀 | O(n²) | 최적의 2배 이하 |
| `two_opt` | 최근접 이웃 경로에서 시작해 개선이 없을 때까지 교차 간선 교체 | O(n²) × 반복 횟수 | 지역 최적 |
| `held_karp` | 비트마스크 DP로 정확한 최적해 계산 (기준값 용도) | O(n²·2ⁿ) | 최적 |

공통 규칙:
- 입력은 점 좌표 목록이고, 출력은 방문 순서(점 번호 목록)**만**이다.
- 경로 길이는 알고리즘 밖(벤치마크·테스트)에서 공통 함수 `tour_length`로 계산한다. 알고리즘 안에서 길이를 계산하면 측정용 거리 계산이 경로 탐색 비용에 섞이기 때문이다.
- Held-Karp는 DP 표에서 최적 길이가 거리 계산 없이 나오므로, 그 값이 필요할 때를 위해 `held_karp_solve`가 (경로, 길이)를 함께 돌려준다.
- 모든 방식이 같은 거리 함수(유클리드)를 쓴다.
- 거리 함수에는 호출 횟수를 세는 기능을 둔다.

## 3. 입력 데이터

| 유형 | 생성 방법 | 최적값 |
|---|---|---|
| 무작위 | 정사각형 영역 안에서 균일 분포로 점을 뽑음 | 작은 n만 (Held-Karp) |
| 군집형 | 군집 중심 몇 개를 정하고 그 주위에 가우시안 분포로 점을 뽑음 | 작은 n만 (Held-Karp) |
| 격자 | 간격 1인 m×k 격자, 한 변은 짝수. 점 순서는 seed로 섞음 | 항상 n |
| TSPLIB | 공개 인스턴스 5개 (아래 표) | 알려진 최적값 |

**격자 크기**

| n | 8 | 10 | 12 | 14 | 100 | 200 | 500 | 1000 | 2000 |
|---|---|---|---|---|---|---|---|---|---|
| m×k | 2×4 | 2×5 | 3×4 | 2×7 | 10×10 | 10×20 | 20×25 | 25×40 | 40×50 |

한 변이 짝수인 격자는 길이 1인 간선 n개로 한 바퀴를 돌 수 있으므로 최적 길이는 n이다.

**TSPLIB 인스턴스**

| 인스턴스 | n | 최적값 |
|---|---|---|
| eil51 | 51 | 426 |
| berlin52 | 52 | 7542 |
| kroA100 | 100 | 21282 |
| ch150 | 150 | 6528 |
| a280 | 280 | 2579 |

- 출처: [TSPLIB95](https://comopt.ifi.uni-heidelberg.de/software/TSPLIB95/). 최적값은 같은 사이트의 `tsp/TSP-BEST.html`에서 가져왔다.
- 파일은 `data/tsplib/`에 있다. 좌표 파일(`.tsp`)과 함께 같은 사이트의 최적 경로 파일(`.opt.tour`)도 넣었다.
- 다섯 개 모두 `EUC_2D` 형식이다. 공식 최적값은 **간선마다 거리를 반올림한 정수**로 계산된 값이다. 그래서 TSPLIB 초과율을 낼 때는 경로 길이도 같은 규칙으로 계산한다.
- 최적 경로를 반올림 규칙으로 계산하면 다섯 개 모두 표의 최적값과 정확히 같다(테스트로 확인).
- 같은 경로를 반올림 없이 계산하면 0.02%(kroA100)~0.94%(eil51) 길게 나온다. 규칙을 섞어 쓰면 초과율이 이만큼 틀어진다.

**재현성**
- 무작위, 군집형, 격자(섞는 순서) 입력은 (유형, n, 인스턴스 번호)마다 고정 seed로 만든다.
- 같은 명령을 다시 돌리면 같은 입력이 나온다.

## 4. 비교 기준

| 기준 | 지표 |
|---|---|
| 속도 | **주 지표: 거리 계산 횟수.** 보조 지표: 실행 시간(반복 측정의 중앙값) |
| 품질 (최적값을 알 때) | 초과율 = (경로 길이 − 최적 길이) ÷ 최적 길이 × 100% |
| 품질 (최적값을 모를 때) | MST 대비 비율 = 경로 길이 ÷ MST 길이 |
| 확장성 | n을 키울 때 실행 시간과 거리 계산 횟수의 기울기(log-log)를 이론 차수와 비교 |
| 이론 대조 | MST 2-근사가 실제로 2배 안에 드는지, 실측 품질이 각 방식의 보장값과 얼마나 떨어져 있는지 |

**거리 계산 횟수의 정의**
- 알고리즘이 **경로를 찾는 동안** 호출한 거리 함수 횟수만 센다.
- 결과 경로의 길이를 재는 계산(돌아오는 간선 포함)은 측정용이므로 세지 않는다. 벤치마크는 알고리즘에는 세는 거리 함수를 넘기고, 길이는 세지 않는 거리 함수로 따로 계산한다.
- 이 정의에서 최근접 이웃, MST 2-근사, Held-Karp의 거리 계산 횟수는 모두 정확히 n(n−1)/2이다. 셋 사이의 실행 시간 차이는 거리 계산이 아닌 나머지 연산에서 나온다. 거리 계산 횟수가 방식마다 달라지는 것은 개선 반복 횟수에 따라 늘어나는 2-opt뿐이다.
- 실행 시간 측정에도 같은 원칙을 적용한다. 길이 계산은 시간 측정 구간 밖에서 한다.

**MST 대비 비율을 읽는 법**
- MST 길이는 최적 길이 이하이다. 그래서 이 비율은 실제 "최적 대비 비율"의 **상한**이 되고, 초과율보다 크게 나온다.
- 따라서 큰 n의 MST 대비 비율을 작은 n의 초과율과 **직접 비교하지 않는다**.
- MST 대비 비율은 같은 입력 안에서 세 방식을 서로 비교하는 데만 쓴다.

## 5. 실험 구성

| 실험 | 입력 | n | 품질 기준 |
|---|---|---|---|
| A. 작은 n | 무작위, 군집형, 격자 | 8, 10, 12, 14 | Held-Karp 최적값 대비 초과율 |
| B. 큰 n | 무작위, 군집형 | 100, 200, 500, 1000, 2000 | MST 대비 비율, 세 방식 상호 비교 |
| B. 큰 n | 격자 | 100, 200, 500, 1000, 2000 | 최적값(n) 대비 초과율 |
| C. TSPLIB | TSPLIB 5개 | 51 ~ 280 | 알려진 최적값 대비 초과율 |
| D. 시작점 민감도 (보조) | 실험 A·B·C와 같은 입력 | 실험 A·B·C와 같음 | 시작점별 초과율(또는 MST 대비 비율)의 최소·중앙값·최대 |

- 무작위와 군집형은 조합마다 seed가 다른 인스턴스를 여러 개(기본 10개) 쓴다. 시간은 여러 번 재서 중앙값을 쓴다.
- 같은 입력의 알고리즘들은 시간을 **번갈아** 잰다. 라운드마다 모든 알고리즘을 한 번씩 돌리고, 라운드마다 시작 알고리즘을 한 칸씩 돌린다. 측정 도중 컴퓨터 상태가 바뀌어도 특정 알고리즘만 불리해지지 않게 하기 위해서이다.
  - 실험 A를 한가한 상태에서 여러 번 잰 사전 측정에서, 그룹별 시간 중앙값(절대값)은 실행마다 평균 11~35%, 최대 119%까지 달랐다.
  - 반면 같은 실행 안의 알고리즘 사이 시간 비율(예: 2-opt ÷ 최근접 이웃)은 실행마다 평균 1~3%만 달랐다. 번갈아 재기를 하든 안 하든 비슷했다.
  - 실험 B에서도 무작위 n=500 그룹만 최근접 이웃 시간이 군집형의 약 2배로 측정되는 등 절대 시간이 튀었다. 같은 인스턴스 안의 알고리즘 사이 비율은 유지됐다.
  - 그래서 **속도의 주 지표는 거리 계산 횟수**로 한다. 하드웨어와 실행 시점의 영향을 받지 않고 다시 돌리면 정확히 같은 값이 나오기 때문이다.
  - 실행 시간은 **보조 지표**로만 쓴다. 절대값(ms)보다는 같은 실행 안에서의 상대 비교(예: MST ÷ 최근접 이웃)와 증가 추세(log-log 기울기) 위주로 해석한다.
  - 거리 계산 횟수가 같은 알고리즘끼리(최근접 이웃과 MST 2-근사) 속도 차이를 설명할 때는 실행 시간 비율을 근거로 쓴다. 이 경우 차이는 거리 계산이 아닌 나머지 연산에서 나온다.
  - 번갈아 재기는 실험 A에서는 측정 가능한 개선이 없었다. 한 알고리즘의 측정이 수 초씩 걸리는 실험 B에서 측정 도중 생기는 흔들림이 한쪽에 몰리지 않게 하는 안전장치로 유지한다.
- 2-opt는 우선 **n ≤ 1000**까지만 잰다. 시간이 남으면 n = 2000 이상으로 넓힌다.
- 결과는 `results/*.csv`로 저장하고, 그래프는 CSV에서 다시 그린다.

**시작점 규칙과 실험 D**
- 실험 A·B·C에서 최근접 이웃은 항상 점 0에서 시작한다. 2-opt의 초기 경로도 점 0에서 시작한 최근접 이웃이다. 세 방식의 조건을 같게 맞추기 위해서이다.
- 무작위·군집형에서 점 0은 사실상 무작위로 고른 시작점이므로, 인스턴스 여러 개의 평균에 시작점 영향이 섞여 들어간다.
- TSPLIB는 인스턴스마다 시작점 하나(파일의 첫 점)의 결과라 시작점 운에 크게 좌우된다. 사전 측정에서 eil51은 시작점에 따라 초과율이 18.1~47.4%로 달라졌다.
- 2-opt도 같은 영향을 받는다. 지역 최적이 여러 개이고, 어느 곳에 도착할지가 초기 경로와 교체 순서에 달려 있기 때문이다. 사전 측정에서 eil51의 2-opt 초과율은 시작점에 따라 1.4~9.9%였다(최근접 이웃은 13.1~32.2%). 같은 최근접 이웃 경로를 회전만 해서 검사 순서만 바꿔도 1.9~9.2%로 비슷하게 퍼졌다.
- 그래서 실험 D에서 여러 시작점으로 돌려 결과의 퍼짐을 따로 잰다. 세 가지를 같은 시작점 집합으로 측정한다.
  1. **최근접 이웃 (시작점 s)**: 점 s에서 시작한 최근접 이웃
  2. **2-opt (시작점 s)**: 1의 경로를 초기 경로로 한 2-opt. 초기 경로와 검사 순서가 함께 바뀐다.
  3. **2-opt (회전 s)**: 점 0에서 시작한 최근접 이웃 경로를 s칸 회전해 초기 경로로 준 2-opt. 경로 모양은 같고 검사 순서만 바뀐다.
- 시작점 집합
  - 작은 n(8~14)과 TSPLIB: 모든 시작점
  - 큰 n(100~2000): seed로 고른 시작점 20개 (모든 시작점은 n배 시간이 든다). 2-opt는 실험 B와 같이 n ≤ 1000
- 기록할 값
  - 시작점별 초과율(최적값을 모르면 MST 대비 비율)
  - 요약: 최소·중앙값·최대, 점 0 결과의 순위
  - 시작점별 최근접 이웃 결과와 2-opt 결과의 상관계수
- 실험 D의 목적은 품질의 퍼짐을 보는 것이라 실행 시간은 재지 않는다.
- 보고서에서 TSPLIB의 최근접 이웃·2-opt 결과를 해석할 때는 실험 D의 분포를 함께 보여 준다.

## 6. 테스트

`unittest`로 작성한다. 개발 중에 `py -m unittest`로 계속 돌린다.

- **경로 유효성**: 모든 점을 정확히 한 번씩 방문하는 순열인지 확인한다. 세 방식과 Held-Karp에 모두 적용한다.
- **길이 계산**: 손으로 계산할 수 있는 작은 예(정사각형 등)에서 값이 맞는지 확인하고, TSPLIB 반올림 규칙도 확인한다.
- **Held-Karp 정확성**: n ≤ 8에서 전수 탐색 결과와 같은지 확인한다.
- **이론 보장**:
  - MST 2-근사 ≤ 2 × 최적
  - 2-opt ≤ 시작 경로(최근접 이웃)
  - 모든 방식 ≥ 최적
- **격자 최적값**: 작은 격자에서 Held-Karp 결과가 n인지 확인한다.
- **거리 계산 횟수**: 경로 탐색 비용만 세는지 확인한다. 최근접 이웃·MST 2-근사·Held-Karp는 정확히 n(n−1)/2번이어야 한다.
- **재현성**: 같은 seed로 만든 입력이 매번 같은지 확인한다.
- **경계 입력**: n = 1, 2, 3과 좌표가 겹치는 점을 확인한다.
